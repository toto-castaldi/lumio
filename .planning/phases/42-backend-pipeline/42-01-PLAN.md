Add a `parseYaml()` helper function that wraps pure YAML content in `---\n...\n---\n` delimiters and delegates to the existing `parseFrontmatter()`:

```typescript
function parseYaml(content: string): Record<string, unknown> {
  const wrapped = `---\n${content}\n---\n`;
  const { frontmatter } = parseFrontmatter(wrapped);
  return frontmatter;
}
```

Add a `LANGUAGE_WHITELIST` constant near the top of the file (after the types section):
```typescript
const LANGUAGE_WHITELIST = ["it", "en", "es", "fr", "de", "pt", "ja", "zh", "ko", "ru", "ar"];
```

In `handleCreate()`, insert a new branch AFTER the `.lumioignore` handling and BEFORE the `filePath.endsWith(".md")` check. The branch should:
1. Match `fileName === "deck.yaml"` (exact filename, case-sensitive)
2. Parse content with `parseYaml(content)`
3. Extract `display_name` and `description` as trimmed strings. If either is empty/missing, log and return success with "skipped" message (silent skip per locked decision)
4. Derive `subfolder_path` from `filePath`: `filePath.substring(0, filePath.lastIndexOf("/") + 1)` -- always has trailing `/`
5. Normalize tags: get array from parsed YAML, map to lowercase with spaces-to-dashes, slice to first 5
6. Validate language: if not in LANGUAGE_WHITELIST, default to `"en"`
7. Extract author as-is from YAML (webhook does not enforce -- that is commit_yaml's job)
8. Upsert into `deck_index` with `{ onConflict: "repository_id,subfolder_path" }` using all fields: repository_id (from repo.id), subfolder_path, display_name, description, tags, author, language
9. On upsert error, log and return `{ success: false }`
10. Clear error state on the repository (follow existing pattern: set sync_status to "synced", null out error fields)
11. Return `{ success: true, message: "deck.yaml indexed: ..." }`

In `handleUpdate()`, insert the same deck.yaml branch AFTER `.lumioignore` and BEFORE `isImageFile()`. Use UPSERT (not UPDATE) for both create and update -- this handles out-of-order webhook delivery (per pitfall #3 from research). The logic is identical to handleCreate's deck.yaml branch.

Important: Do NOT add deck.yaml handling to the image handling path. deck.yaml is a text file, so it flows through the text content decoding section naturally.
