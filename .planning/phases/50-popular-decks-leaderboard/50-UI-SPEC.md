## Component Inventory

### Section: `.popular-decks`

Structure: `<section class="popular-decks">` placed in `index.html` after `.features` and before `.screenshots`.

```
.popular-decks
  h2                          -- Section heading (bilingual)
  .leaderboard-list           -- Ordered list container (ol element)
    .leaderboard-entry        -- Single deck row (li element), repeated up to 10x
      .entry-rank             -- Position number: "#1", "#2", etc.
      .entry-info             -- Flex column containing name + metadata
        .entry-name           -- Deck display_name text
        .entry-meta           -- Flex row: subscriber count + language flag
          .entry-subscribers  -- "24 subscribers" / "24 iscritti" (bilingual span)
          .entry-lang         -- Flag emoji
      .entry-tags             -- Flex row of tag chips
        .tag-chip             -- Individual tag (max 3 visible, overflow hidden)
```

### Leaderboard Entry Row

- Background: `var(--card-bg)`
- Border: `1px solid rgba(124, 58, 237, 0.15)` (matches `.feature-card`)
- Border-radius: `14px` (matches `.feature-card`)
- Padding: `1rem 1.5rem` (16px vertical, 24px horizontal)
- Layout: CSS flexbox, `align-items: center`, `gap: 1rem`
- No hover state change (entries are not interactive, per CONTEXT.md decision)
- No cursor pointer, no link wrapping

### Tag Chip

- Background: `rgba(124, 58, 237, 0.15)`
- Color: `var(--purple-primary)`
- Font: 0.75rem, weight 700
- Padding: `0.25rem 0.5rem` (4px vertical, 8px horizontal)
- Border-radius: `6px`
- Max visible: 3 chips per entry. If more than 3 tags exist, show first 3 only with no overflow indicator.

### Rank Number

- Color: `var(--amber-primary)` #F59E0B
- Font: 0.95rem, weight 700
- Min-width: `2rem` (ensures alignment for single and double digit numbers)
- Text-align: right

## Layout Contract

### Section Placement

Insert between `.features` and `.screenshots` in `index.html`. The section is conditionally rendered: if the fetch returns zero decks, do NOT insert the section into the DOM at all.

### Desktop (min-width: 768px)

- `.leaderboard-list`: single column, max-width 700px, centered with `margin: 0 auto`
- `.leaderboard-entry`: horizontal flex row with rank, info, and tags on one line
- `.entry-tags`: flex-wrap allowed, right-aligned or after info block

### Mobile (max-width: 767px)

- `.leaderboard-entry`: same horizontal layout at reduced padding (`0.75rem 1rem`)
- `.entry-tags`: wrap below name/meta on narrow viewports if needed

### Small Screen (max-width: 480px)

- `.leaderboard-entry`: flex-wrap allowed, tags wrap to new line below entry-info
- `.entry-rank`: stays inline with entry-info
- Tags row gets full width below the name/meta content

## Interaction Contract

### Data Fetch

- Trigger: `DOMContentLoaded` event (alongside existing language init in `script.js`)
- Method: Direct Supabase REST API call via `fetch()` to avoid adding dependencies (landing page currently has zero npm dependencies)
- Endpoint: `POST {SUPABASE_URL}/rest/v1/rpc/top_decks` with `apikey` header (anon key)
- On success with results: build and insert `.popular-decks` section into DOM
- On success with empty array: do nothing (section never appears)
- On fetch error: do nothing (section never appears, fail silently)

### Language Toggle

- All text content uses existing bilingual `<span lang="en/it">` pattern
- Language toggle button already in `script.js` handles visibility via CSS rules
- No additional JS needed for language switching

### States

| State | Visual Treatment |
|-------|-----------------|
| Loading | Section not in DOM yet, no spinner, no skeleton |
| Data loaded (1+ decks) | Section injected into DOM between Features and Screenshots |
| Empty (0 decks) | Section never injected, invisible to user |
| Fetch error | Section never injected, invisible to user, no error banner |
| Language toggle | Bilingual spans swap via existing CSS `display: none !important` rules |

## Copywriting Contract

| Element | EN Copy | IT Copy |
|---------|---------|---------|
| Section heading | Popular Decks | Deck Popolari |
| Subscriber count (singular) | {n} subscriber | {n} iscritto |
| Subscriber count (plural) | {n} subscribers | {n} iscritti |
| Primary CTA | not applicable (no CTA in this section) | not applicable |
| Empty state heading | not applicable (section hidden when empty) | not applicable |
| Empty state body | not applicable (section hidden when empty) | not applicable |
| Error state | not applicable (section hidden on error) | not applicable |
| Destructive confirmation | not applicable (no destructive actions) | not applicable |

Bilingual implementation: every text node uses `<span lang="en">...</span><span lang="it">...</span>` wrapping. The subscriber count number is shared outside the spans; only the label word is inside the spans.

Example markup pattern:
```html
<span class="entry-subscribers">
  {count}
  <span lang="en">subscribers</span>
  <span lang="it">iscritti</span>
</span>
```

For singular (count === 1):
```html
<span class="entry-subscribers">
  1
  <span lang="en">subscriber</span>
  <span lang="it">iscritto</span>
</span>
```

## Accessibility Contract

- Section heading is `<h2>` (same heading level as Features, Screenshots, Download CTA)
- Leaderboard uses `<ol>` semantic element (ordered list for ranked content)
- Each entry is `<li>` within the `<ol>`
- Tag chips are purely visual, no interactive role needed
- Language flag emojis get `aria-hidden="true"` with a visually-hidden text label for screen readers
- Subscriber count uses `aria-label` on the container for clear screen reader output: e.g. `aria-label="24 subscribers"`
- Color contrast: `--text-light` (#F5F3FF) on `--bg-dark` (#0F0A1A) exceeds WCAG AAA (ratio > 15:1). `--text-secondary` (#A78BFA) on `--card-bg` (#1A1230) meets WCAG AA (ratio ~4.7:1). `--amber-primary` (#F59E0B) on `--card-bg` (#1A1230) meets WCAG AA (ratio ~5.2:1).
