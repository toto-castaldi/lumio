**1. CardRenderer.ts** -- Custom react-native-marked Renderer:

Extend `Renderer` from `react-native-marked` implementing `RendererInterface`:

- **constructor(isDark: boolean):** Store isDark for theme-dependent rendering.

- **code(text, language?, containerStyle?, textStyle?):** Override to use `react-native-code-highlighter`:
  ```typescript
  import CodeHighlighter from 'react-native-code-highlighter';
  import { atomOneDark, atomOneLight } from 'react-syntax-highlighter/dist/esm/styles/hljs';
  ```
  Return `<CodeHighlighter>` with:
  - `key={this.getKey()}` (CRITICAL: prevents duplicate key warnings per research pitfall 3)
  - `hljsStyle={this.isDark ? atomOneDark : atomOneLight}`
  - `language={language || 'text'}`
  - Container style: borderRadius 8, padding 12, marginVertical 8, backgroundColor from theme (isDark ? '#111827' : '#f3f4f6')
  - Text style: fontSize 14, fontFamily 'monospace'

- **codespan(text, styles?):** Override to detect LaTeX vs regular inline code:
  - If text starts with `$` or `\\(` or `\\[` -- this is LaTeX from the tokenizer. Render `<KaTeXView expression={text} displayMode={false} isDark={this.isDark} />`.
  - Otherwise render default inline code with theme-aware background.
  - Use `key={this.getKey()}` on root element.

- **image(uri, alt?, style?):** Override for full-width images:
  - Return `<Image>` with `width: '100%'`, `aspectRatio: 16/9` (default), `borderRadius: 8`, `marginVertical: 8`, `resizeMode: 'contain'`.
  - Add `accessibilityLabel={alt || 'Card image'}`.
  - Use `key={this.getKey()}`.

**2. CardTokenizer.ts** -- Custom MarkedTokenizer for LaTeX detection:

Extend `MarkedTokenizer` from `react-native-marked`:

- **codespan(src):** Override to detect inline LaTeX `$...$`:
  ```typescript
  const match = src.match(/^\$+([^\$\n]+?)\$+/);
  if (match?.[1]) {
    return { type: 'codespan', raw: match[0], text: match[1].trim() };
  }
  return super.codespan(src);
  ```

- **Override paragraph or relevant method** to detect display LaTeX `$$...$$`:
  If content between `$$...$$` is found, emit it as a code token that the renderer can detect and render as a display-mode KaTeXView. Consider checking if react-native-marked's default tokenizer already handles `$$` blocks -- if it passes them through as code blocks with a specific language, the renderer can detect them there instead. The key is that display math `$$...$$` renders as `<KaTeXView displayMode={true}>`.

**3. KaTeXView.tsx** -- Micro-WebView for LaTeX rendering:

Create a React component that renders a single LaTeX expression using KaTeX in a minimal WebView:

Props: `{ expression: string; displayMode: boolean; isDark: boolean; }`

Implementation:
- Generate minimal HTML with KaTeX CSS + JS from CDN (same CDN versions as current cardHtml.ts: katex@0.16.9)
- Call `katex.render(expression, element, { displayMode, throwOnError: false })` in the WebView
- Use `postMessage` to report rendered height back to React Native
- Set WebView background to transparent
- Start with `opacity: 0` and fade in once height is reported (prevents flash per research pitfall 4)
- Set reasonable initial height: 24px for inline, 60px for display mode
- WebView should have `scrollEnabled={false}`, `originWhitelist={['*']}`, `javaScriptEnabled={true}`

Theme integration:
- Text color: isDark ? '#f9fafb' : '#333333'
- Background: transparent (parent handles background)

Memoize the HTML string with `useMemo` depending on `[expression, displayMode, isDark]`.

**Important patterns from research:**
- Always use `this.getKey()` for unique keys in custom renderer methods
- Memoize renderer/tokenizer instances in the consuming component (CardContentView), not here
- KaTeXView must handle both inline (small, inline-flex) and display (full-width, block) modes

**1. Rewrite CardContentView.tsx** -- Replace WebView with react-native-marked:

Remove all WebView-related code. New implementation:

```typescript
import React, { useMemo } from 'react';
import { type ViewStyle } from 'react-native';
import Markdown from 'react-native-marked';
import { useTheme } from '../../hooks/useTheme';
import { CardRenderer } from './CardRenderer';
import { CardTokenizer } from './CardTokenizer';
```

Props stay the same: `{ content: string; isDark: boolean; style?: ViewStyle; }`

Inside the component:
- Memoize renderer: `const renderer = useMemo(() => new CardRenderer(isDark), [isDark]);`
- Memoize tokenizer: `const tokenizer = useMemo(() => new CardTokenizer(), []);`
- Build theme object for react-native-marked using colors from `useTheme()`:
  ```typescript
  const markdownTheme = useMemo(() => ({
    colors: {
      background: 'transparent', // Let parent control background
      text: isDark ? '#f9fafb' : '#333333',
      link: isDark ? '#60a5fa' : '#3B82F6',
      border: isDark ? '#374151' : '#e5e7eb',
      code: isDark ? '#111827' : '#f3f4f6',
    },
  }), [isDark]);
  ```

- Return `<Markdown>` component:
  ```tsx
  <Markdown
    value={content}
    flatListProps={{
      style: style,
      scrollEnabled: false, // Parent handles scrolling in preview, FlatList handles in modal
      contentContainerStyle: { paddingHorizontal: 16, paddingVertical: 8 },
    }}
    renderer={renderer}
    tokenizer={tokenizer}
    theme={markdownTheme}
  />
  ```

  **CRITICAL:** Set `scrollEnabled: false` here because CardContentView is used INSIDE CardPreviewModal which manages its own scrolling. The react-native-marked FlatList should NOT scroll independently -- the modal's layout handles it. See pitfall 2 from research about VirtualizedList nesting.

  **Alternative:** If react-native-marked's FlatList with scrollEnabled=false causes issues inside the modal, consider switching to `flatListProps={{ scrollEnabled: true }}` and letting the FlatList be the sole scroll container (remove any parent ScrollView). Test and choose the approach that works.

Remove the import of `generateCardHtml` and `WebView`. The old `cardHtml.ts` file is no longer used by CardContentView but may still be referenced elsewhere -- do NOT delete it in this plan (it may be needed for WebView in StudyScreen quiz cards).

   ```
   Modal -> Pressable backdrop -> View (sheet, flex) -> drag handle + header + View (flex:1) -> CardContentView (Markdown/FlatList fills space)
   ```
   The FlatList inside react-native-marked should have `scrollEnabled: true` so it scrolls within the bottom-sheet. Pass this via the `flatListProps` in CardContentView.

   This means CardContentView needs to accept a prop for scrollEnabled. Add an optional `scrollEnabled?: boolean` prop to CardContentView, defaulting to false. CardPreviewModal passes `scrollEnabled={true}`.

c) **Add PanResponder for swipe-down dismiss** on the drag handle area:
   ```typescript
   import { PanResponder, Animated } from 'react-native';
   ```

   Create a PanResponder that:
   - Tracks vertical drag on the handle/header area
   - Uses an `Animated.Value` for translateY
   - When released: if translateY > 100px threshold, call `onClose()`; otherwise spring back to 0
   - Wrap the sheet View in `<Animated.View style={{ transform: [{ translateY }] }}>`

   The PanResponder should ONLY attach to the drag handle area (not the whole sheet), so it doesn't conflict with FlatList scrolling.

d) **Update header** -- keep the title but remove the close button. Simplify the header layout since there's no button on the right:
   ```tsx
   <View style={[styles.header, { borderBottomColor: colors.border }]}>

       {card?.title || 'Card Content'}
     </Text>
   </View>
   ```

e) **Keep existing functionality:**
   - Pressable backdrop tap-to-dismiss stays
   - Modal onRequestClose (Android back button) stays
   - Bottom-sheet styling (80% height, rounded corners, elevation) stays
   - Empty state when card is null stays
   - Image URL resolution through CardView stays

f) **Update CardContentView usage** -- pass `scrollEnabled={true}` and remove the ScrollView wrapper:
   ```tsx
   <View style={{ flex: 1 }}>
     {card ? (
       <CardContentView content={content} isDark={isDark} scrollEnabled={true} />
     ) : (
       <View style={styles.emptyState}>...</View>
     )}
   </View>
   ```

g) **Clean up styles** -- remove `scrollView` and `scrollContent` styles (no longer needed), remove `closeButton` style.

h) **Clean up imports** -- remove ScrollView import (no longer used), remove Ionicons if no longer used.
