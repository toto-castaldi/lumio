**StudyScreen.tsx — Pin the bottom button:**

In `renderStudying()` (around line 243), restructure the layout so the next-card button container is absolutely positioned at the bottom of the screen rather than being a sibling of the ScrollView in the flex column.

Current structure:
```
<View style={{ flex: 1 }}>
  <QuizCard ... />             ← ScrollView with flex: 1
  {userAnswer !== null && (
    <View bottomStyles.container>  ← sits below ScrollView
      <NextButton />
    </View>
  )}
</View>
```

Target structure:
```
<View style={{ flex: 1 }}>
  <QuizCard ... />             ← ScrollView, add extra paddingBottom when answered
  {userAnswer !== null && (
    <View style={[bottomStyles.container, { position: 'absolute', bottom: 0, left: 0, right: 0, ... }]}>
      <NextButton />
    </View>
  )}
</View>
```

Steps:
1. When `session.userAnswer !== null`, the bottom button container should use `position: 'absolute'`, `bottom: 0`, `left: 0`, `right: 0` so it floats over the bottom of the screen.
2. Pass a prop (e.g. `extraBottomPadding`) to QuizCard or adjust its `contentContainerStyle` paddingBottom to account for the button height (~80px + insets.bottom) so scrollable content is not hidden behind the button. The simplest approach: add a `bottomInset` prop to QuizCard that adds to its contentContainerStyle paddingBottom. Or, compute it in StudyScreen and pass it. The button container is roughly 16 (paddingTop) + 16*2 (paddingVertical of button) + 16 (paddingBottom) + insets.bottom ≈ ~80 + insets.bottom pixels. Round up to 100 + insets.bottom for safety.
3. Keep the existing `backgroundColor: colors.surface` and `borderTopWidth: 1` on the bottom container so the button has a solid background and doesn't look like it's floating over content.

**AnswerOption.tsx — Fix dark mode backgrounds:**

Currently `backgroundColor` for `correct` and `incorrect` states uses hardcoded light pastels:
- correct: `#ecfdf5` (green-50 — nearly white)
- incorrect: `#fef2f2` (red-50 — nearly white)

These are unreadable in dark mode because `colors.text` is `#f9fafb` (white).

Fix:
1. Destructure `isDark` from `useTheme()` (it already imports `useTheme`).
2. Change the `backgroundColor` closure:
   - `correct`: `isDark ? '#064e3b' : '#ecfdf5'` — dark green (emerald-900) vs light green-50
   - `incorrect`: `isDark ? '#7f1d1d' : '#fef2f2'` — dark red (red-900) vs light red-50
3. Change the `borderColor` closure for dark mode:
   - `correct`: keep `#10b981` (works fine on both)
   - `incorrect`: keep `#ef4444` (works fine on both)
4. The `optionText` color uses `colors.text` which is `#f9fafb` in dark mode. On dark green/red backgrounds this has excellent contrast. On light mode backgrounds it uses `#333333`. No change needed for text color.
