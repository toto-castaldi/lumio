2. **Source of Truth**: Explain that `.planning/STATE.md` contains a `Milestone: vX.Y` field. This is the single source of truth for the app version. To bump the version, update this field (e.g., `Milestone: v1.8`).

3. **Extraction Script**: Document `scripts/extract-version.cjs`:
   - Reads `.planning/STATE.md`
   - Parses the `Milestone: vX.Y` line with regex
   - Generates `packages/shared/src/version.ts` with the extracted version
   - Prints the version to stdout (for CI to capture)
   - Exit code 1 if STATE.md not found or no Milestone field
   - Zero npm dependencies — runs with any Node.js

4. **CI Pipeline**: Document how CI uses the version in `.github/workflows/ci-deploy.yml`:
   - `lint-and-typecheck`: Runs `extract-version.cjs` before `build:packages` to ensure TypeScript sees the correct version
   - `build-apk`: Extracts version and passes it as `-PversionName` to Gradle
   - `deploy-functions`: Extracts version and sets `LUMIO_VERSION` env var for Edge Functions
   - `deploy-landing`: Extracts version and injects it into `index.html` via sed before SCP deploy

5. **Consumers**: List all places that consume the version:
   - `packages/shared/src/version.ts` — exports `VERSION`, `BUILD_INFO`, `getVersionString()`, `getFullVersionString()`
   - Android app Settings screen — imports from `@lumio/shared`
   - Edge Functions `/version` endpoint — reads `LUMIO_VERSION` env var
   - Landing page footer — `__LUMIO_VERSION__` placeholder replaced by CI

6. **How to Bump the Version**: Step-by-step:
   - Edit `.planning/STATE.md`, change `Milestone: vX.Y` to the new version
   - Commit and push to main
   - CI automatically propagates the new version to all consumers

7. **Version Format**: Document that GSD versioning uses `major.minor` only (no patch). Example: `1.7`, `1.8`, `2.0`. No git tags, no CHANGELOG, no conventional commits.

8. **Legacy**: Brief note that legacy tooling (husky, commitlint, commitizen, release-please, auto-release CI, git tags, CHANGELOG.md) was removed in v1.7 Phase 20.

Keep the document concise and practical. Use code blocks for file paths and commands. No unnecessary prose.
