## Ancillary Finding

**Count/Session Overdue Branch Asymmetry** (Minor, pre-existing from Phase 26):
`get_due_card_count` counts cards via `card_review_schedule` without joining `card_questions`. `get_study_cards_for_session` requires `HAVING COUNT(cq.id) > 0`. If a scheduled card has all questions deactivated, the dashboard counter may read slightly higher than the actual session delivers. Not a v2.2 regression — intentional design trade-off preserved from Phase 26.
