**5. Replace random selection with sequential iteration:**
- REMOVE `seenCardIds` ref entirely
- REMOVE `selectRandomCard` function entirely
- Replace `loadNextQuestion` to iterate sequentially:
  - Use a `nextCardIndex` ref (initialized to 0) that tracks the position in the `cards` array
  - Instead of picking random cards, take `cards[nextCardIndex.current]` and increment
  - If a card has no question (getPreGeneratedQuestion returns null), increment and try the next card
  - When `nextCardIndex.current >= cards.length`, return null (session complete)
  - The retry loop still exists to skip cards without questions, but iterates forward instead of random

**6. Add fire-and-forget SRS write-back in `handleNext`:**
Inside the `setSession` callback where the current answered card is saved to `answeredCards`, also fire the SRS write-back. Use the pattern:

```typescript
// Fire SRS write-back (does NOT block navigation)
const isCorrect = prev.userAnswer === prev.currentQuestion.correctAnswer;
const quality = isCorrect ? 4 : 1;
const card = prev.currentCard as SRSStudyCard;

// Fire-and-forget with single retry (per CONTEXT.md)
recordCardReviewWithRetry(card.id, quality, card.contentHash);
```

Add a helper function OUTSIDE the hook (module-level) for the retry:
```typescript
async function recordCardReviewWithRetry(
  cardId: string,
  quality: number,
  contentHash: string
): Promise<void> {
  try {
    await recordCardReview(cardId, quality, contentHash);
  } catch (err) {
    // Retry once silently
    try {
      await recordCardReview(cardId, quality, contentHash);
    } catch (retryErr) {
      // Drop the update — card will appear again as if not reviewed
      console.error('SRS write-back failed after retry:', retryErr);
    }
  }
}
```

IMPORTANT: The write-back must NOT be awaited in the navigation flow. Fire it as a detached promise — do NOT add `await`. Per CONTEXT.md: "Per-answer SRS writes persist immediately (fire-and-forget per SC#4), so quitting mid-session does NOT lose already-answered updates."

IMPORTANT: Skip must NOT trigger write-back. Per CONTEXT.md: "Skipping a card = no SRS schedule update."

**7. Track which cards have been written back:**
Add a `writtenBackCardIds` ref (`useRef<Set<string>>(new Set())`) to avoid double writes when navigating back to a previously answered card. In the fire-and-forget section, only fire if the card hasn't been written back yet:
```typescript
if (!writtenBackCardIds.current.has(card.id)) {
  writtenBackCardIds.current.add(card.id);
  recordCardReviewWithRetry(card.id, quality, card.contentHash);
}
```

**8. Update computed values:**
- `effectiveLimit` should now be `totalCards` (the actual number of cards after filtering, since overdue cards already bypass the cap in the RPC)
- `progress` should be `answeredCount / totalCards` where answeredCount includes the currently-answered card
- `cardsRemaining` should be `Math.max(0, totalCards - seenCount)` where seenCount tracks the `nextCardIndex` position

**9. Preserve handleGoToCard:**
This function navigates to a previously answered card. Keep it as-is — it shows old answers without triggering SRS write-back (which is correct since we track writtenBackCardIds).

**10. Preserve handleSkip:**
Keep the skip functionality, but it now advances `nextCardIndex` without any SRS write. This is already correct since the write-back only fires in handleNext when there IS an answer.
