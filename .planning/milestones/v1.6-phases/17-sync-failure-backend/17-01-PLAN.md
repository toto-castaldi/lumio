Create a SQL migration that:

1. **Add `failed` to sync_status enum:**
   ```sql
   ALTER TYPE sync_status ADD VALUE IF NOT EXISTS 'failed';
   ```
   This must be in its own transaction (PostgreSQL requirement for ALTER TYPE ADD VALUE). Supabase migrations run each file as a single transaction, so this needs a workaround — use `DO $$ ... $$` with `ALTER TYPE` outside a transaction block is NOT possible in a migration. Instead, since Supabase applies migrations with `BEGIN/COMMIT`, we need to check if the value exists first and add it only if missing. Use the standard pattern:
   ```sql
   DO $$
   BEGIN
       IF NOT EXISTS (SELECT 1 FROM pg_enum WHERE enumlabel = 'failed' AND enumtypid = 'sync_status'::regtype) THEN
           ALTER TYPE sync_status ADD VALUE 'failed';
       END IF;
   END $$;
   ```
   **IMPORTANT:** `ALTER TYPE ADD VALUE` cannot run inside a transaction in PostgreSQL. Supabase migrations handle this by running the migration outside a transaction when it detects `ALTER TYPE ... ADD VALUE`. So use the bare statement directly:
   ```sql
   ALTER TYPE sync_status ADD VALUE IF NOT EXISTS 'failed';
   ```

2. **Add columns to repositories table:**
   - `sync_error_type TEXT` — stores Docora's raw error_type string (e.g., "auth_error", "rate_limit", "network_error")
   - `is_auth_error BOOLEAN NOT NULL DEFAULT FALSE` — computed by the webhook handler based on error_type containing "auth" (per Claude's Discretion: using a boolean flag is cleaner for Phase 19 than raw string checks in the app)
   - `sync_failed_at TIMESTAMPTZ` — when the failure occurred (per locked decision)

3. **Add index** on sync_status for efficient filtering of failed repos (already exists as idx_repositories_sync_status, no action needed).

4. **Add comments** on new columns explaining their purpose.

Do NOT drop or modify any existing columns. Use `ADD COLUMN IF NOT EXISTS` for safety.

**2. Add handleSyncFailed function** (after handleDelete, before the serve handler):

```typescript
async function handleSyncFailed(
  serviceClient: ReturnType<typeof createClient>,
  payload: DocoraErrorPayload
): Promise<{ success: boolean; message: string }> {
  const { repository, error_type, error_message } = payload;

  // Find Lumio repository by Docora ID
  const repo = await findRepositoryByDocoraId(
    serviceClient,
    repository.repository_id
  );

  // Unknown repos: ignore silently, return 200 OK (per locked decision)
  if (!repo) {
    console.log("[handleSyncFailed] Unknown repository, ignoring:", repository.repository_id);
    return { success: true, message: "Unknown repository, ignored" };
  }

  // Determine if this is an auth error (Claude's Discretion: check if error_type contains "auth")
  const isAuthError = error_type.toLowerCase().includes("auth");

  // Update repository with failure details (idempotent — always overwrite per locked decision)
  const { error: updateError } = await serviceClient
    .from("repositories")
    .update({
      sync_status: "failed",
      sync_error_type: error_type,
      sync_error_message: error_message,
      is_auth_error: isAuthError,
      sync_failed_at: new Date().toISOString(),
    })
    .eq("id", repo.id);

  if (updateError) {
    console.error("[handleSyncFailed] DB update error:", updateError.message);
    return { success: false, message: `Failed to store error: ${updateError.message}` };
  }

  console.log(`[handleSyncFailed] Stored failure for repo ${repo.id}: type=${error_type}, is_auth=${isAuthError}`);
  return { success: true, message: `Sync failure recorded: ${error_type}` };
}
```
