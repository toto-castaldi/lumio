Enforce session card limits end-to-end: the `get_study_cards_for_session` RPC caps total cards (overdue + new) to `p_limit`, prioritizing overdue cards (oldest first). Purpose: Users who choose "20 cards" must receive exactly at most 20 cards, not an unlimited number of overdue cards. This is the core enforcement that makes session size selection meaningful.

Output: Updated SQL RPC, updated core TS function, renamed type, updated hook and settings.

**Step 3 (return query):** Replace the current UNION ALL with logic that respects the total cap:

When `p_limit IS NULL` (Auto/unlimited):
- Return ALL overdue cards ordered by `next_review_at ASC` (most overdue first)
- UNION ALL with ALL new cards (no LIMIT on new cards)

When `p_limit IS NOT NULL` (capped):
- Overdue cards: `ORDER BY crs.next_review_at ASC LIMIT p_limit` (cap overdue at p_limit)
- Compute `v_overdue_returned` as `LEAST(v_due_count, p_limit)`
- New cards: `LIMIT GREATEST(0, p_limit - v_overdue_returned)` (fill remaining slots)

Implementation approach: Use an IF/ELSE block inside the function body. In the `p_limit IS NULL` branch, return the overdue UNION ALL new with no LIMIT clauses. In the `p_limit IS NOT NULL` branch, LIMIT overdue to `p_limit` and new cards to `GREATEST(0, p_limit - LEAST(v_due_count, p_limit))`.

Keep all existing logic intact: stale schedule row deletion (Step 1), timezone handling, GROUP BY, HAVING, JOIN conditions. Only the LIMIT clauses and the branching change.

Update the COMMENT ON FUNCTION to reflect the new behavior: "When p_limit is NULL, returns all cards (unlimited). When p_limit is set, caps total to p_limit with overdue-first priority."
